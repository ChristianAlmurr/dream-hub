# /dream apply

The instructions for `/dream apply`. `.claude/commands/dream.md` sends you here; nothing in that file's propose part applies.

1. Run `python3 scripts/dream_proposal.py`: it prints the path of the store's open proposal, the only one that can be applied. If it says there is none, still do step 2: the script then lists what earlier proposals left waiting for a session. Do those as step 3 says, reporting each as the script tells you, and stop after step 4; if it says nothing waits, say so and stop.
2. Run `python3 scripts/dream_apply.py`. It applies the ticked items of that proposal itself, each change as its own checked, logged and committed write (agent `dreamer`, session `dream-<stem>`, where `<stem>` is the proposal's file name without `-proposal.md`: `dream-2026-11-12`, or `dream-2026-11-12-2` for the second proposal of that day), and records what became of every item in `memory/dreams/<stem>-applied.json`. Don't apply, repeat or reword anything it handled. An item it reports as `refused` (the store's `reject.txt` or the credential check refused the content, the line to change is gone or was named inexactly, the words fit several lines) stays unapplied: report it with its reason. Don't reword it to get it through.
   - If the script stops with a message instead of a list of items (an apply already running, a record it can't read, an error), say the message and stop there. Apply nothing by hand.
3. Do only what it lists under "Needs a session", and after each one run `python3 scripts/dream_apply.py --done <item>`. If it also lists what earlier proposals left waiting for a session, do those the same way and report each with `--done <item> --of <proposal file name>`, as it says:
   - a new skill: write it to the path the script printed, `.claude/skills/<name>/SKILL.md` in this repo, and leave it uncommitted for me to review.
   - a scratchpad: rewrite `agents/<agent>/scratch.md` down to what the item says to keep, with `python3 scripts/memwrite.py read|write … --agent dreamer --session dream-<stem> --why '<the item>' --force`.
   - an accepted inbox item: do what the inbox file proposes unless a numbered item already did, then remove the file with `git -C memory rm`.
   Anything else is not yours to do by hand: report it.
4. **Don't touch `memory/ORG.md`, and don't edit the Steering block of `.claude/commands/dream.md`.** That tier is mine. The script lists those ticked items under "Yours" with the two commands I run myself; you can't lift the lock on `ORG.md`, and the script won't. `memory/INDEX.md` is generated, so never edit it.
5. Run `python3 scripts/memcheck.py --seal` and report anything it finds. Then close the proposal, as the last step and only once every ticked item is written or reported: `python3 scripts/dream_proposal.py applied`, with no numbers: the script's record says what became of each item, and what was refused, is mine or still needs a session is handed on as ticked. Without it no later dream starts. If it says nothing is ticked, stop and tell the person what it said. Then stop and report what the script printed: what was applied, what was already there, what was refused and why, what is waiting for me, the commit hashes from `git -C memory log --oneline -n 20`, and what that last command said.
